# iogrpc Architecture

## System Layers

1.  **Transport (iohttp)**: Manages `io_uring` event loop, TLS (wolfSSL), and `nghttp2`.
2.  **H2 Adapter**: Bridges `nghttp2` streams to gRPC semantics. Dispatches based on `:path` and `content-type`.
3.  **gRPC Core**: Manages stream state machine, frame parsing (LPM), metadata, and status.
4.  **Service Registry**: Typed handlers generated by `protoc-gen-iogrpc-c`.

## Execution Model

- **Thread-per-core**: Each stream is pinned to a single worker thread. No cross-thread context migration for active streams.
- **Async I/O**: All operations must be non-blocking, using `io_uring` completions.
- **Arena Memory**: Use `iogrpc_arena_t` for per-call allocations. Cleanup is performed in a single step upon stream closure.

## Core Components

- `iogrpc_server_t`: Global server state and service registry.
- `iogrpc_call_t`: Context for a single RPC (metadata, deadline, cancel token).
- `iogrpc_stream_ctx_t`: Internal state machine for HTTP/2 stream to gRPC mapping.

## Workflow

1.  Define service in `.proto`.
2.  Generate C stubs using `protoc-gen-iogrpc-c`.
3.  Implement typed handlers using the arena for response allocation.
4.  Register service with `iogrpc_server_register_service()`.
